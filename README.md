# 삼복출프 (SBCP)

소규모 학원의 출결을 학생이 직접 체크하고, 집계된 결과를 AI가 주간 리포트 문장으로 옮겨 주는 웹 서비스입니다.

**배포 URL** — https://sbcp-attendance.vercel.app/

**GitHub** — https://github.com/Hoyasiro/sbcp-attendance

**서비스 기획서** — [docs/서비스기획서.md](docs/서비스기획서.md)

---

## 1. 서비스 소개

학원 원장이 매주 학부모에게 보낼 출결 리포트를 손으로 쓰는 일을 줄이는 것이 목적입니다.

- 학생이 2자리 번호로 등·하원을 직접 체크합니다
- 출석률·연속 출석·평균 체류 시간이 자동으로 집계됩니다
- **등급 판정은 JavaScript가 하고, AI는 그 결과를 문장으로 옮기기만 합니다**
- 학부모 발송용 / 학생 열람용 두 가지 톤으로 리포트를 생성합니다

### 설계 원칙 — 판정은 코드, 문장은 AI

같은 데이터로 몇 번을 생성해도 등급이 달라지면 안 됩니다.
그래서 출석률 계산과 등급 판정은 모두 코드가 처리하고,
AI에게는 확정된 등급과 숫자를 넘겨 **문장만 쓰게** 했습니다.

프롬프트에도 다음 규칙을 명시했습니다.

- 등급은 이미 정해져 있다. 절대 다시 판단하지 마라
- 숫자를 지어내지 마라
- 주어진 정보에 없는 이름·사실을 지어내지 마라

## 5. 로컬 실행 방법

### 사전 준비

```bash
npm i -g vercel
```

확인 (개발 시 사용한 버전: Vercel CLI 59.10.0)

```bash
vercel --version
```

**Windows 사용자 주의** — Vercel CLI는 리눅스 기준으로 `python3` 명령을 찾습니다.
Windows에는 `python`만 있으므로, Python 설치 폴더에서 `python.exe`를
같은 위치에 `python3.exe`라는 이름으로 복사해 두어야 합니다.

### 실행

```bash
git clone https://github.com/Hoyasiro/sbcp-attendance.git
cd sbcp-attendance
vercel dev
```

브라우저에서 `http://localhost:3000` 접속.

> HTML 파일을 더블클릭해서 여는 방식(`file://`)이나 Live Server로는
> AI 기능이 동작하지 않습니다. `/api/` 경로를 처리할 서버가 없기 때문입니다.

## 6. 환경 변수 설정

이 서비스는 Gemini API 키가 필요합니다. **키는 코드에 적지 않고 환경 변수로만 관리합니다.**

| 변수명 | 설명 |
|---|---|
| `GEMINI_API_KEY` | Google AI Studio에서 발급받은 API 키 |

### 로컬

프로젝트 루트에 `.env` 파일을 만들고 아래와 같이 작성합니다.

```
GEMINI_API_KEY=YOUR_API_KEY_HERE
```

`.env`는 `.gitignore`에 등록되어 있어 저장소에 올라가지 않습니다.

### 배포 (Vercel)

`.env`가 저장소에 올라가지 않으므로, 배포 환경에는 키를 따로 등록해야 합니다.

1. Vercel 프로젝트 → **Settings → Environment Variables**
2. Key `GEMINI_API_KEY`, Value에 발급받은 키 입력
3. **Sensitive 토글을 켠 상태**로 저장 (저장 후 값을 다시 볼 수 없게 됩니다)
4. 재배포

> 환경 변수는 **배포 시점에 주입**됩니다.
> 값만 추가하고 재배포하지 않으면 기존 배포에는 반영되지 않습니다.

### 왜 환경 변수인가

- `js/main.js`에 적으면 브라우저가 파일을 통째로 내려받으므로 누구나 볼 수 있습니다
- `api/report.py`에 적으면 브라우저에는 안 보이지만, **공개 저장소에 그대로 노출**됩니다
- 환경 변수를 쓰면 코드에는 변수 이름만 남고, 실제 값은 코드 밖에 있습니다

## 7. 배포 방법

GitHub 저장소를 Vercel에 연결하면 `main` 브랜치에 푸시할 때마다 자동으로 재배포됩니다.

1. Vercel → **Add New → Project** → 저장소 선택
2. **Application Preset을 `Other`로 지정** ← 중요
3. Environment Variables에 `GEMINI_API_KEY` 등록
4. **Deploy**

> **2번이 중요한 이유**: `requirements.txt`가 있으면 Vercel이 Python 프레임워크
> 프로젝트로 감지하는 경우가 있고, 그러면 `api/` 폴더의 파일 기반 함수가
> 무시되어 API가 404가 됩니다. `Other`로 지정하면 이 문제를 피할 수 있습니다.
> 자세한 경위는 아래 개발 로그의 `[S6] vercel dev 502` 항목에 있습니다.

### 배포 확인 순서

프론트를 열어 보기 전에 백엔드부터 확인하면 문제 범위를 좁힐 수 있습니다.

```
https://sbcp-attendance.vercel.app/api/report
```

주소창에 직접 입력했을 때 **`501 Unsupported method ('GET')`** 이 나오면 정상입니다.
이 함수는 POST만 받으므로 GET을 거부하는 것이 올바른 동작입니다.
404가 나오면 함수 자체를 인식하지 못한 상태입니다.

## 8. AI 기능 명세

### 요청 / 응답

```
POST /api/report

요청  { "data": "출결 요약 텍스트", "tone": "parent" | "student" }
응답  { "ok": true,  "text": "리포트 문장" }
      { "ok": false, "error": "사용자에게 보여줄 안내 문구" }
```

성공과 실패를 같은 모양으로 돌려주기 때문에 프론트의 분기 코드가 단순해집니다.

### 데이터 흐름

```
[브라우저]
  번호 입력 → weeklyStats()로 집계·등급 판정 (JS)
           → 카드 4개 + 등급 배지 표시
           → buildReportData()로 AI에게 넘길 텍스트 생성
           → fetch('/api/report')
                    │
[Vercel Serverless Function] api/report.py
           → os.environ에서 키를 읽음
           → Gemini 호출 (timeout 25초, thinking_level: low)
           → 필요한 필드만 추려 JSON 반환
                    │
[브라우저]
           → renderReportText()로 화면에 표시
```

### 실패 처리

| 상황 | 화면 동작 | API 호출 |
|---|---|---|
| 번호 미입력 | 생성 버튼이 표시되지 않음 | 없음 |
| 미등록 번호 | "등록되지 않은 번호입니다" | 없음 |
| 이번 주 기록 0건 | "이번 주 출결 기록이 없습니다" | 없음 |
| 네트워크 끊김 | "연결에 실패했습니다. 네트워크 상태를 확인해 주세요." | 실패 |
| API 오류 (4xx/5xx) | 백엔드가 보낸 안내 문구 표시 | 실패 |
| 응답 지연 | 버튼이 "작성 중..."으로 바뀌고 안내 문구 표시 | 진행 중 |

외부 API의 원문 에러 메시지는 화면에 노출하지 않습니다.
개발자용 상세 원인은 `print()`와 `console.error()`로 분리했습니다.

### API 호출을 줄이기 위한 장치

AI API는 호출마다 과금이 발생하므로, 불필요한 호출을 네 겹으로 차단했습니다.

| 상황 | 호출 | 방법 |
|---|---|---|
| 빈 입력 · 미등록 번호 | ✕ | 버튼 숨김 + 입력 검증 |
| 이번 주 기록 0건 | ✕ | 집계 결과로 사전 판단 |
| 같은 조건 재요청 | ✕ | 2단 캐시 (메모리 + localStorage) |
| 요청 중 버튼 연타 | ✕ | 버튼·입력칸 잠금 |
| 데이터 또는 톤 변경 | ⭕ | 캐시 키가 달라짐 |

## [S3] CSS/JS 파일 분리 중 발생한 오류

![](screenshot/01_console_error.png)

- **증상** — 파일 분리 후 사이드바 버튼이 동작하지 않음. `Uncaught ReferenceError: goTab is not defined`
- **추적** — Network 탭 확인 결과 `main.js`가 요청 목록에 **아예 없음**. 404가 아니라 목록에 없다는 것은 브라우저가 요청조차 하지 않았다는 뜻

![](screenshot/02_network_확인.png)

- **원인** — HTML에 `<script src="js/main.js">` 누락. 잘라내기 과정에서 빈 `<script></script>`만 남아 있었음
- **해결** — `<script src="js/main.js"></script>`로 수정

![](screenshot/03_정상동작.png)

- **배운 점** — Console 에러는 증상, Network 탭은 원인. "파일이 404다"와 "파일을 요청도 안 했다"는 다른 문제다

## [S4] 모바일 레이아웃 전면 붕괴

![](screenshot/04_before_mobile_출결데스크.png)

- **증상** — 375px에서 사이드바가 260px를 차지해 본문이 뭉개짐. 스크롤도 되지 않음
- **원인** — `@media` 쿼리가 0개. 스크롤 차단이 `body` / `.main-content` / `.screen` **3중으로** 걸려 있었음
- **해결** — `@media (max-width:768px)` 블록을 기존 CSS 아래에 추가. 사이드바를 하단 고정 탭바로 전환, 스크롤 3중 해제, 내부 그리드를 1열로

![](screenshot/05_after_mobile_출결데스크.png)

- **배운 점** — 기존 CSS를 고치지 않고 아래에 덮어쓰는 규칙만 추가하면 되돌리기 쉽다

## [S5] Gemini API 응답 구조 파악

![](screenshot/07_gemini_응답구조_확인.png)

- **상황** — 공식 문서가 SDK 기준으로만 설명하고 REST 응답 JSON 예시를 제공하지 않음
- **시도** — AI Studio에서 코드 확인 → 요청 형식만 나오고 응답 형식은 없음
- **해결** — 임시 스크립트로 실제 호출한 뒤 응답 전체를 출력해 구조를 직접 확인
- **결과** — `steps[]` 배열에서 `type == "model_output"`인 항목의 `content[0].text`에 답변이 있음

```json
{
  "status": "completed",
  "steps": [
    { "type": "thought", "signature": "..." },
    { "type": "model_output", "content": [ { "type": "text", "text": "답변" } ] }
  ]
}
```

- **주의점** — 순서(`steps[1]`)로 찾으면 안 된다. thought 단계가 없는 경우가 있으므로 **`type`으로 찾아야** 한다
- **부수 발견** — 인사 한 문장에 thought 토큰 183개 소모. 출력 토큰 7개의 26배

## [S5] vercel dev 로그인 실패 — ByteString 변환 오류

- **증상** — `Cannot convert argument to a ByteString because the character at index 0 has a value of 50724`
- **추적** — 50724가 유니코드 코드값임에 착안
  1. `$env:USERNAME` 확인 → `rxtee`, 영문이므로 무관
  2. `$env:COMPUTERNAME` 확인 → 한글 이름
  3. '오'의 코드값이 50724와 일치
- **원인** — CLI가 기기 이름을 HTTP 헤더에 담아 전송하는데, HTTP 헤더는 ASCII만 허용
- **1차 해결** — Vercel 토큰으로 로그인 단계를 우회. 토큰 입력 시 `Read-Host` 붙여넣기가 동작하지 않아 `Get-Clipboard`로 클립보드에서 직접 읽어 해결
- **최종 해결** — PC 이름을 영문으로 변경 후 재부팅 → 토큰 없이 정상 실행
- **배운 점** — 우회로를 만드는 것보다 원인을 제거하는 편이 빠를 때가 있다

## [S5] python3 명령을 찾지 못함

- **증상** — `uv is required ... python3 -m pip install ... Python was not found`
- **원인** — Windows는 `python`, 리눅스/맥은 `python3`. Vercel CLI가 리눅스 기준으로 `python3`를 찾음
- **해결** — `python.exe`를 같은 폴더에 `python3.exe`로 복사
- **배운 점** — 로컬(Windows)과 배포(Linux) 환경의 차이를 처음으로 체감한 사례

## [S5] requirements.txt 파싱 실패 — BOM 문제

- **증상** — `could not parse requirements.txt: Unexpected '癤'` → 내용을 고친 뒤에는 `Unexpected ''`
- **1차 시도** — 한글 주석이 원인이라 판단해 영문으로 변경 → 실패
- **재추적** — VS Code 상태바에 `UTF-8 with BOM` 표시 확인
- **원인** — PowerShell `Out-File -Encoding utf8`이 파일 앞에 BOM 3바이트를 삽입. 내용을 바꿔도 인코딩 설정은 유지되어 문제가 지속됨
- **해결** — VS Code에서 인코딩을 BOM 없는 UTF-8로 변경 후 저장
- **배운 점** — 눈에 보이지 않는 문자도 파일 내용이다. 에디터의 인코딩 표시를 확인하는 습관이 필요하다

## [S6] vercel dev 502 — requirements.txt가 프레임워크 감지를 유발

- **증상** — `.vercel` 재생성 과정에서 `NO_RESPONSE_FROM_FUNCTION`
- **시도 1** — `pyproject.toml`로 entrypoint 명시 → Windows 경로의 `\Users`를 파이썬이 유니코드 이스케이프로 해석해 `SyntaxError`
- **시도 2** — `pyproject.toml` 제거 → entrypoint를 찾지 못함 (양자택일 불가 상태)
- **재추적** — 처음 성공했던 시점의 조건과 비교 → 그때는 `requirements.txt`가 없었음
- **원인** — `requirements.txt`의 존재가 Python 프레임워크 감지를 유발. 프레임워크 프리셋이 잡히면 `api/` 폴더의 파일 기반 함수가 무시됨
- **해결** — `requirements.txt` 제거 후 프로젝트 재생성 → `No framework detected` 확인. 이후 파일을 복구해도 설정이 유지되어 정상 동작
- **배운 점** — 성공했던 시점과 지금의 차이를 비교하는 것이 유효한 디버깅 방법이다
- **후속** — 이 문제는 S7 배포 단계에서 다시 등장했고, Application Preset을 `Other`로 지정하는 것으로 더 간단히 해결했다

## [S6] 다른 학생의 집계 결과가 화면에 남는 문제

- **증상** — 01번 리포트를 생성한 뒤 번호를 02로 바꿔도, 화면의 집계 카드는 01번의 값이 그대로 남아 있음
- **원인** — 카드를 그리는 `renderReportStats()`를 호출하는 곳이 `generateReport()` 하나뿐이었음. 즉 카드는 **버튼을 눌러야만** 갱신되는 구조였고, 이름 표시만 입력 이벤트에 연결되어 있어 이름과 카드가 서로 다른 학생을 가리키는 상태가 발생
- **해결** — `refreshReportStats()`를 신설해 입력 이벤트에 연결. 다음 규칙을 코드로 고정
  - 카드는 항상 "지금 입력창에 있는 번호"의 것이어야 한다
  - 유효한 번호가 아니면 카드도 리포트도 남기지 않는다
- **부수 효과** — 버튼을 누르지 않아도 번호만 입력하면 집계가 표시되므로, 집계만 확인하고 싶을 때 API를 호출할 필요가 없어졌다
- **배운 점** — 화면에 보이는 값이 두 군데에서 따로 갱신되면 반드시 어긋나는 순간이 생긴다. 갱신 시점을 한 곳으로 모으는 것이 해법이었다

## [S6] 리포트 캐시 도입

![](screenshot/19_cache_no_api_call.png)

- **문제 인식** — 같은 학생, 같은 집계값, 같은 톤이면 AI에게 물어볼 내용이 동일한데도 버튼을 누를 때마다 매번 호출되고 있었음. 호출당 과금이 발생하고 응답에 20초 이상 걸리므로 개선 필요
- **설계** — 집계값 전체를 조합해 캐시 키를 만들고, 키가 있으면 저장된 문장을 재사용

```
키 = 학생ID | 주 시작일 | 출석일 | 운영일 | 연속 | 평균체류 | 등급 | 톤
```

- **키에 집계값을 모두 넣은 이유** — 학생이 추가로 출석하면 키가 달라져 자동으로 새로 호출된다. 데이터가 바뀌었는데 옛 리포트를 보여 주는 사고를 막기 위함
- **키에 톤을 넣은 이유** — 학부모용과 학생용은 문장이 달라야 하므로 다른 질문으로 취급해야 함
- **2단 구조** — 메모리(빠름, 새로고침 시 소멸) + localStorage(브라우저를 껐다 켜도 유지). 앱 시작 시 localStorage 내용을 메모리로 올려 두고, 조회는 메모리만 확인

![](screenshot/20_cache_localstorage.png)

- **실패 결과는 저장하지 않음** — 에러를 캐시하면 네트워크가 복구된 뒤에도 계속 에러가 표시되기 때문

## [S7] 주말에 평일 기준 집계를 검증할 수 없었던 문제

## [S7] 주간 평균과 월간 합계가 어긋나 보인 사례
